# ADR 0002. Адрес назначения webhook ограничен публичной сетью

Статус: принято. Затрагивает RFC §10.

## Что было решено в RFC

«В рамках задания ограничиваемся запретом переадресаций, таймаутом 5 секунд и лимитом
на размер ответа в 64 КБ. Полноценный список разрешённых адресов и защита от подмены DNS —
за границей задания, отмечается в README как известное ограничение.»

## Что изменилось

Перед отправкой имя из `webhook_url` разрешается, и запрос отвергается, если хотя бы один
полученный адрес лежит вне публичной сети: приватные диапазоны, loopback, link-local
(включая `169.254.169.254`), multicast, зарезервированные. Отказ постоянный — повторять
запрещённый адрес незачем.

Исключения задаются списком `WEBHOOK_ALLOWED_HOSTS`. В демонстрационном окружении там
`api`: приёмник из RFC §11 живёт внутри сети compose и без исключения недостижим.

## Почему

Оговорка в RFC была написана до того, как отправка появилась в коде. Сейчас сервис
действительно ходит POST'ом на адрес, названный клиентом, изнутри сети — то есть работает
управляемым извне прокси во внутренний периметр: метаданные облака, собственная база,
админки соседних сервисов. Запрет переадресаций закрывает только второй хоп, а не первый,
и без проверки самого адреса он ничего не решает.

Цена вопроса — сорок строк и один список исключений. Оставлять дыру, которая закрывается
дешевле, чем описывается в README, неправильно.

## Что осталось незакрытым

Между проверкой и подключением адрес может измениться: httpx резолвит имя заново, поэтому
подмена DNS между двумя разрешениями не ловится. Полное закрытие требует подключения к
уже проверенному адресу с подстановкой `Host`, а с TLS — ещё и сверки сертификата с именем.
Это заметно больше кода, и в README остаётся строкой про известное ограничение.

## Что отвергли

- **Оставить как в RFC и ограничиться записью в README.** Документировать уязвимость дешевле,
  чем её чинить, но здесь разница в объёме работы — часы против минут.
- **Белый список адресов вместо чёрного.** Правильнее, но требует от клиента заранее
  зарегистрировать адрес, а такого контракта в задании нет.
- **Проверка на валидации `POST /payments`.** Не заменяет проверку перед отправкой: между
  созданием платежа и webhook проходит время, и запись в DNS за это время может измениться.
